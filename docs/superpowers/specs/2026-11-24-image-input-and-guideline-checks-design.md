# 이미지 입력(학생부 캡처·스캔) + 공식근거 추가 점검 설계

날짜: 2026-11-24 / 상태: 승인됨 (사용자: "추가기능은 공신력 출처 조사 후 알아서 수정")

## 목적

타인이 쓴 교과세특(학생부 캡처·사진·스캔 PDF)을 이미지로 읽어 기존 검토 파이프라인
(기재금지·과목분리·문체·오탈자)에 태우고, 공식 문서 근거의 점검을 추가한다.

## 근거 (공신력 출처만; 조사 보고서 = scratchpad research_report.md)

- 2026학년도 기재요령(고등, star.moe.go.kr): 모든 항목 기재불가 p.18-19(인쇄쪽 기준),
  세특 입력불가 p.118(1·2학년)/p.149(3학년), 한글·영문 표기 p.28, 생성형 AI 결과 그대로
  입력 금지·윤문 후 허위·과장 확인 의무 p.19. 훈령 제555호(시행 2026.3.1.).
- 한글 맞춤법(문체부고시 제2017-12호) 제41~47항 띄어쓰기, 문장 부호(제2014-39호)
  제8·9항 따옴표, 제17항 물결표(범위 표기 허용). 공식 맞춤법 검사 API는 없음.
- Gemini API 공식문서: 이미지 PNG/JPEG/WEBP/HEIC/HEIF, 인라인 요청 20MB 미만, PDF 50MB·1,000쪽
  입력 가능. 약관: 무료 티어는 입력 콘텐츠를 제품 개선에 사용하고 사람이 검토할 수
  있음, 유료는 미사용. 학생부 이미지는 이름·학교명이 그대로 전송됨.
- 2027학년도 기재요령·교육분야 개인정보 가이드라인의 학생부 AI 입력 제한 조항은 미확인
  → 앱은 "2026학년도 기재요령 기준"임을 명시한다.

## 설계

### 1. 이미지 입력 (Mode 1 "기재 금지 표현 검토")

입력 방식 라디오에 3번째 선택지 `이미지로 읽기 (캡처·사진·스캔)` 추가.
흐름: 동의 체크 → 업로드(png/jpg/jpeg/webp + pdf, 여러 장) → `글자 읽기` →
이미지 미리보기(좌)·편집 가능한 전사본(우, key `image_transcript`) → 기존 `검토 실행`.
전사본이 `input_text`가 되어 단일 검토 경로(과목 자동분리 포함) 그대로 동작한다.

- **동의 게이트**: 체크 전에는 업로더 비활성. 문구에 (a) Google Gemini API 외부 전송,
  (b) 무료 키는 약관상 제품 개선 사용·사람 검토 가능 → 학생부 이미지는 유료(결제 활성)
  키에서만, (c) 이름·학번 등은 가리고 올릴 것을 명시.
- **core/ocr.py (신규, 순수 로직)**: `prepare_image(data, mime) -> (bytes, mime)`
  — EXIF 회전 보정, 긴 변 3000px 초과 시 축소, RGBA→RGB, JPEG 재인코딩(품질 90)으로
  용량 절감. 파일당 15MB·총 18MB·최대 10개 한도 검증 `validate_uploads(files)`(위반 시
  ValueError, 한국어 메시지). PDF는 변환 없이 통과(≤18MB).
- **core/gemini.py**: `transcribe_images_with_gemini(parts, api_key) -> str`
  - 시스템 프롬프트: **원문 그대로 전사. 오탈자·띄어쓰기·맞춤법·문장부호를 절대 고치지
    않는다(교정 금지).** 읽기 불확실한 글자는 `⟦?⟧`로 표시. 표 머리글·쪽번호·워터마크는
    제외. 각 과목 세특은 `과목명: 내용` 한 줄 블록(학기 표기는 `(1학기)과목명: ` 허용)으로
    출력해 `split_by_subject`가 분리하게 한다. 해석·요약·설명 문장 금지, 전사본만 출력.
  - temperature 0, thinking 끔. `genai_types.MediaResolution`이 설치된 SDK에 있으면 HIGH
    사용(없으면 생략, try/except).
  - `_GeminiModel.generate_content`가 `contents=`에 Part 리스트를 받을 수 있게 시그니처
    타입만 확장(동작 불변).
  - `verify_transcription_with_gemini(parts, transcript, api_key) -> list[dict]` (선택 기능
    `대조 검증`): 이미지와 전사본을 비교해 불일치 `{"transcript":..., "image":..., "note":...}`
    목록 반환(JSON).
- **전사 후 경고**: `⟦?⟧` 개수 표시, 남아 있으면 "이미지와 대조해 수정" 경고. 개인정보
  자동 마스킹은 이후 텍스트 호출에 기존대로 적용.
- 세특 초안 모드·일괄 모드는 변경 없음. 스캔 PDF 텍스트 추출 실패 시(기존 오류 문구)에
  "이미지로 읽기 모드에서 PDF를 올려 보세요" 안내만 추가.

### 2. 공식 근거 기반 점검 추가

1. **근거 쪽수 병기**: `RULE_PATTERNS`의 basis와 Gemini 심사 basis에 "2026 기재요령 p.18-19"
   (공통 금지) / "p.118·149"(세특 불가) 표기. 모르는 쪽수는 쓰지 않는다(조항명만).
2. **학교 식별정보 안내**: 사이드바 `사용자 정의 금칙어` help에 "우리 학교 이름·별칭·축제명을
   등록하세요(기재요령 p.18-19 블라인드)" 문구 추가(기능 변경 없음).
3. **허위·과장 표현 경고** (`style_check`): 최상급·과장어(예: 최고, 완벽, 독보적, 압도적,
   누구보다, 천재 …)를 정확한 낱말 경계로 검출 → "허위·과장 기재 금지: 직접 관찰 근거 확인"
   권고(위반 아닌 참고). 오탐 최소화를 위해 소수의 명백한 어휘만, 각 어휘 테스트.
4. **물결표 규칙 (2026-11-24 정정)**: `~`(변형 ∼〜～ 포함)는 숫자 범위여도 **항상 경고**하고
   붙임표 `-`로 쓰도록 안내(문장 부호 제17항이 `-` 대체를 허용하고, 현장 지침이 특수기호
   지양이며 기재요령 예시도 기간을 `2026.03.04.-2026.07.08.`로 표기). 자동 치환 보조
   `fix_tilde_ranges`(숫자~숫자 → 숫자-숫자) 제공. (초안의 "범위 표기 허용"은 철회.)
5. **서식 점검 추가(`style_check`)**: 연속 공백 2개 이상, 문장부호 앞 공백, 마침표 뒤 공백
   누락(소수점·약어 제외), 중복 문장부호(`..`, `,,` — 줄임표 `…`/`......` 제외),
   문장 끝 마침표 누락(줄 마지막이 한글인데 부호 없음).
6. **맞춤법 로컬 룰 (`core/rules.py`, API 불필요)**: 한글 맞춤법 근거가 분명한 흔한 오류만
   큐레이션 — 예: 몇일→며칠, 설레임→설렘, 금새→금세, 어떻해→어떻게/어떡해, 안되→안 돼/안돼
   문맥, 됬→됐, 웬지→왠지, 율/률 규칙 일부, 의존명사·보조용언 띄어쓰기(`할수있`, `수있`, `것같`,
   `때문에`는 제외 등). **정밀도 우선**: 규칙마다 긍정·부정 테스트 필수, 확신 없는 규칙은
   제외. 결과는 "맞춤법 점검(로컬 규칙)" 경고로 `style_check`에 합류하며 근거 조항 표기.
7. **AI 윤문 최종 확인 체크리스트**: 수정본/초안 생성 결과 아래에 expander
   "✅ 최종 입력 전 확인(기재요령 p.19)" — 체크박스 3개(학생 실제 수행과 일치·허위·과장
   없음 / 기재요령 유의사항 준수 / 교사가 직접 관찰·평가한 내용). 강제 아님, 안내 목적.
8. **기준 학년도 표시**: `core/rules.py`에 `RULES_BASIS_LABEL = "2026학년도 기재요령(교육부훈령
   제555호) 기준"` 상수, 검토 결과 영역과 사이드바 심사기준 위에 caption으로 표시.

### 3. `split_by_subject` 확장

`(1학기)과목명:` / `(2학기)과목명:` 접두 허용. 반환 과목명에는 학기 접두를 제외하고
학기는 별도 보관하지 않는다(YAGNI). 기존 6과목 예시·단일 텍스트 동작은 불변.

### 4. 줄·문장 위치 기반 통합 오류 리포트 (2026-11-24 추가, 사용자 요청)

교사가 최종 판단하도록 모든 점검 결과를 한 표로 통합: **몇 번째 줄·몇 번째 문장 / 원문 / 오류 내용 / 수정 제안 / 공식 근거·예외 / 판정**.

- **core/report.py (신규, 순수 로직)**: `build_issue_report(text, findings, proofread_items=(), subject_segments=None) -> list[dict]`
  - 이슈 필드: `line`(개행 기준 1부터), `sentence`(해당 줄 안 문장 순번), `subject`(있으면), `start`/`end`(전체 텍스트 문자 오프셋),
    `excerpt`(문제 부분 앞뒤 ~20자, 문제어는 「」로 감쌈), `category`(기재금지/맞춤법/서식/문체/과장·허위), `problem`(오류 내용), `suggestion`(수정 내용),
    `basis`(공식 근거: 문서명·쪽수/조항), `exception`(예외 조건 안내, 없으면 ""), `verdict`.
  - 같은 단어가 여러 번 나오면 **발생 위치마다 별도 행**. 줄바꿈이 한 줄뿐인 긴 단락은 문장 순번이 위치 판단 기준.
  - 판정(`verdict`): 기재금지 위반 → `기재 불가`; 기재금지 주의 → `확인 필요`; 맞춤법·서식 → `수정 필요`; 문체·과장 → `권고`.
    표 위에 종합 판정 한 줄: 불가 N건·확인 필요 N건·수정 필요 N건 → "기재요령 기준 판정(참고) — 최종 판단은 교사".
  - 정렬: 줄 → 문장 → 시작 오프셋. 제거(오탐 무시) 목록과 연동되어 무시된 검출어는 제외.
- **style_check 구조화**: `collect_style_issues(text) -> list[dict]`(span 포함)를 추가하고 기존 `style_check`는 이 결과를
  문자열로 변환하는 얇은 래퍼로 유지(기존 테스트·UI 호환). 맞춤법 로컬 룰·서식·과장·특수문자(물결표 포함) 모두 span 보유.
  물결표·특수문자는 `suggestion`에 치환안(예: `3~4시간 → 3-4시간`) 포함.
- **공식 근거 대조(rulebook)**: `core/rulebook.py` — 조사 보고서 기반 규칙 사전 `RULEBOOK[rule_id] = {title, summary, exceptions, source}`
  (source는 "2026학년도 기재요령(고등) p.18-19" 등 인쇄쪽, 훈령 제555호, 한글 맞춤법 제N항, 문장 부호 제N항). 모든 RULE_PATTERNS 항목·Gemini 기준 9개·
  style 이슈가 rule_id로 연결. 예외 반영: 교육관련기관명(교육부·교육청·교육지원청 및 직속기관) 허용, 독서 도서명·저자명 속 기관·상호명 허용,
  소논문 가능 6과목(수학과제 탐구·사회문제 탐구·융합과학 탐구·과학과제 연구·사회과제 연구·윤리문제 탐구)에서는 `소논문` 검출을
  `확인 필요`로 낮추고 "실적(제목·연구주제·참여인원·소요시간) 제외 시 기재 가능" 예외 문구 표시, 일반화된 영문 약어 허용.
- **UI**: 검토 결과 영역 상단에 "📋 오류 리포트(줄·문장별)" st.dataframe(컬럼: 줄, 문장, 과목, 구분, 원문, 오류 내용, 수정 제안, 근거, 판정) +
  CSV 다운로드. 과목 분리 모드는 과목별 expander 안에서도 같은 형식(줄 번호는 해당 과목 본문 기준이 아니라 **원문 전체 기준**으로 통일).
  행 클릭/선택 UI는 불필요(YAGNI).
- 검증: 줄·문장·오프셋 계산 단위 테스트(다중 발생, 한 줄 긴 단락, 이미지 전사본 `⟦?⟧` 포함), rulebook 예외(교육청 허용·소논문 과목 예외·도서명 예외) 긍정·부정 테스트.

### 5. 전송 전 개인정보 가드 (2026-11-24 추가, 사용자 요청)

사용자 전제: 유료 키 사용, 입력은 학년·과목·수행평가 수준(학교명·이름 제외 예정).

- **core/privacy.py (신규, 순수 로직)**: `scan_identifying_risks(text) -> list[dict]` — 위험 신호 검출:
  지역명 패턴(시·군·구·읍·면·동·리·로·길로 끝나는 지명 어절, 시도명), 따옴표·꺾쇠로 감싼 고유 과제·프로젝트 제목,
  학교명 의심어(○○고/고등학교/여고/중/초 + 축제·별칭 단서), 사람 이름 의심(기존 masking.suggest_mask_candidates 재사용),
  전화·이메일·학번. 각 항목 `{kind, text, start, end, advice}`. 정밀도 우선(일반명사 오탐 최소화), 긍정·부정 테스트.
- **전송 미리보기**: 검토 실행 전 expander "📤 실제로 전송되는 텍스트(마스킹 적용 후)" — `apply_mask`(사용자 마스킹 + 자동 마스킹) 결과 표시,
  위험 신호 목록·조언 표시. 위험 신호가 있으면 검토 실행 버튼 위에 경고 + 체크박스 "위험 신호를 확인했고 그대로 전송합니다"
  (key 명시; 체크 전엔 검토 실행 비활성). 위험 신호 0건이면 게이트 없이 통과.
- **키 등급 안내**: 사이드바 caption에 "Gemini 유료(결제 활성) 키 사용을 전제로 합니다 — 무료 키는 약관상 입력이 제품 개선에 쓰이고 사람이 검토할 수 있음" 상시 표기.
- 이미지 모드는 마스킹 불가 안내 유지(동의 게이트). 텍스트 모드 게이트는 이미지 모드의 전사본 검토에도 동일 적용.
- 범위: Mode 1 단일 검토·이미지 전사본. 일괄 모드는 기존 마스킹 유지(게이트 비적용, 후속).
