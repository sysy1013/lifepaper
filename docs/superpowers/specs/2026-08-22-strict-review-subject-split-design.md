# 세특 검토 엄격화 + 문장부호/영문표기 검사 + 과목별 분류 설계

날짜: 2026-08-22 / 상태: 승인됨

## 목적

기재금지표현 판정을 기재요령(2026학년도 학교생활기록부 기재 길라잡이) 기준으로
엄격화하고, 맞춤법(기존 기능 재확인·연결)·따옴표/괄호 짝 검사·특수문자/영문표기
검사를 추가하며, "과목명: 내용" 형식으로 여러 과목이 한 텍스트에 붙어 있는 입력을
과목별로 자동 분리해 결과를 분류 표시한다.

## 근거 문서 (기재요령 반영 사항)

- 8대 기재금지: 공인어학시험·인증시험, 교내외 대회 성적/수상, 교외상, 모의고사
  성적, 논문/도서출간/지식재산권, 해외활동(어학연수·해외봉사), 부모 사회경제적
  지위 암시, 장학생/장학금, 특정 대학명/기관명/상호명/강사명, 자격증 명칭/취득
- 세특 전용 추가 입력불가(기재요령 p.118, p.149): K-MOOC/MOOC/KOCW, 방과후학교
  활동, 연구보고서(소논문) 실적(제목·연구주제·참여인원·소요시간 — 단 지정 6개
  과목은 실적 제외한 특기사항 서술은 허용), 대회명을 "행사"로 바꿔 쓰는 편법 기재
- 기관명 예시: 유네스코·OECD·UN·IMF·통계청 등 (교육관련기관은 예외)
- 상호명 예시: 구글·네이버·삼성·카카오·유튜브·오픈AI·마이크로소프트·패들렛 등
- 한글 표기 원칙(p.28): 부득이한 경우만 영문 허용 — 외국인 성명/도로명 영문/
  도서명·저자명 고유명사/일반화된 명사(CEO, PD, UCC, IT, POP, CF, TV, PAPS,
  SNS, PPT, AI)·단위 등은 예외
- 특수문자·문단구분기호(번호) 입력 지양 (p.40)

## 설계

### 1. 기재금지표현 엄격화 — `core/rules.py` + `core/gemini.py`

**RULE_PATTERNS 확장**(규칙 기반, API 불필요, 항상 실행):
기관명(유네스코/OECD/UN/IMF/통계청 등), 자격증 명칭 예시, 대회/수상 관련 표현,
논문/학회지/투고/등재/출간, 지식재산권(특허/실용신안/상표권), 해외활동(어학연수/
해외봉사/교환학생), 장학생/장학금, K-MOOC/MOOC/KOCW, 방과후학교, 소논문,
대학명 매칭을 접미사 기반(`[가-힣]{2,10}대학교?`)으로 일반화, 브랜드 목록에
오픈AI·마이크로소프트·패들렛·삼성 추가. 신규 매치는 기존과 동일하게 `severity:
"주의"`로 병합.

**SYSTEM_PROMPT(Gemini) 강화**: 위 "근거 문서" 항목을 기준별 예시와 함께 명시하고,
"애매하면 놓치지 말고 최소 '주의'로 표시하라(과소탐지보다 과탐지가 안전)"는
판단 원칙과 "대회명을 단순 행사로 바꿔 쓴 경우도 위반으로 탐지" 지시를 추가한다.
기존 8개 기준에 "K-MOOC/MOOC/KOCW·방과후학교·연구보고서(소논문) 실적" 1개
기준을 추가해 9개 기준으로 확장.

기존 인터페이스(`review_text`, `review_text_masked`, `analyze_with_gemini`)는
시그니처 변경 없음 — 프롬프트/패턴 내용만 강화.

### 2. 맞춤법·띄어쓰기 검사 — 기존 기능 연결

`proofread_with_gemini` + `render_proofread_block`은 이미 구현되어 있음(오탈자·
맞춤법·띄어쓰기·조사 오용). 신규 코드 불필요. 4번 과목별 분류 모드에서 이 기능도
과목 세그먼트 단위로 호출되도록 연결한다(아래 4번 참조).

### 3. 따옴표/괄호 짝 검사 + 특수문자/영문표기 검사 — `core/rules.py`

`style_check()`가 반환하는 경고 목록에 아래 3개 검사를 추가한다(모두 규칙 기반,
API 불필요, 기존 UI `render_style_warnings`의 "📝 문체·표현 점검" 확장 패널에
자동으로 노출됨 — 신규 UI 불필요).

- **따옴표/괄호 짝 검사**: `'`, `"`, `(`/`)` 각각 검사. 따옴표류는 개수가
  홀수면 마지막 등장 위치를 "짝이 맞지 않는 지점"으로 지목하고 주변 15자
  컨텍스트를 함께 표시. 괄호는 스택 기반으로 미매칭 위치를 정확히 찾아
  표시(따옴표류보다 신뢰도 높음).
- **특수문자·문단구분기호 사용 지양**: 원문자(①②…), ★☆●○◆◇▶※ 등 불릿류,
  줄 시작의 번호 매기기(`1)`, `2.` 등)를 정규식으로 탐지해 경고.
- **한글 표기 원칙(영문 오남용) 검사**: 라틴 문자 토큰(`[A-Za-z]{2,}`)을
  찾아 화이트리스트(CEO, PD, UCC, IT, POP, CF, TV, PAPS, SNS, PPT, AI 및
  단위류 km/cm/kg/mm 등)에 없으면 "영문 표기 검토 필요"로 경고. 도서명·
  외국인 성명 등 정당한 예외는 오탐 가능 — 다른 검출 항목과 동일하게
  교사 확인 후 무시 가능한 "권장 사항"으로 취급(하드 에러 아님).

세 검사 모두 문자열 경고 리스트를 반환하며 `style_check()` 내부에서 합쳐진다.
(1번의 규칙 기반 확장과 달리 이 검사들은 findings 테이블이 아닌 문체 점검
경고로 노출 — 기존 UI 패턴과 일치.)

### 4. 과목별 자동 분류 — `core/parsing.py` (신규 함수) + `core/gemini.py` + `app.py`

**분리 함수** `split_by_subject(text: str) -> list[tuple[str, str]]`:
줄 시작에서 `과목명: ` 패턴(`^([가-힣Ⅰ-Ⅻ·]{2,15}):\s*(?=\S)`, MULTILINE)을
찾아 다음 매치 전까지를 해당 과목의 본문으로 묶는다. 매치가 2개 미만이면
`[("", text)]`(과목 라벨 없음)를 반환해 기존 단일 텍스트 동작과 100% 호환.

**단일 입력 모드**: 입력 텍스트에서 `split_by_subject` 결과가 2개 이상이면
자동으로 "N개 과목 감지됨" 안내를 띄우고, 과목별로 (기재금지표현 규칙+Gemini
검토, 문체 점검, 맞춤법 검사)를 각각 실행해 과목별 `st.expander`로 결과를
그룹핑해 보여준다. 세그먼트가 1개면 기존 단일 검토 화면 그대로 동작(회귀 없음).
새 오케스트레이션 함수 `review_text_masked_multi(segments, major, api_key,
custom_words, mask_map) -> list[dict]`를 `core/gemini.py`에 추가 —
세그먼트별로 `review_text_masked`를 호출하고 각 finding에 `"subject"` 키를
채워 하나의 리스트로 합친다. 맞춤법 검사도 동일하게 세그먼트별 반복 호출.

**명렬표/파일 일괄 업로드 모드**: `run_batch_review_pipeline`의 `_review_job`
내부에서도 각 학생 텍스트에 `split_by_subject`를 적용 — 2개 이상이면
`review_text_masked_multi`로 교체 실행하고 결과 findings에 `subject`가 채워진
채로 저장된다(기존 반환 스키마 그대로, `subject` 키만 추가되므로 하위 호환).
학생별 상세 expander에 과목별 소계(예: "🔬 물리학 2건, 💻 정보 1건")를 추가
표시한다. 세그먼트가 1개뿐인 학생(과목 라벨 없는 기존 방식 입력)은 현재와
동일하게 표시.

## 검증

1. `core/rules.py` 신규 함수(따옴표/괄호/특수문자/영문표기/split_by_subject)
   단위 테스트 — 정상 케이스, 홀수 따옴표, 괄호 미매칭, 화이트리스트 영문,
   과목 미검출(1개 이하 세그먼트) 케이스 포함.
2. RULE_PATTERNS 확장분 회귀 — 기존 `tests/test_rules.py` 통과 + 신규 패턴
   케이스 추가.
3. 실 API 없이 스텁으로 `review_text_masked_multi` 병합·subject 태깅 검증.
4. 기존 단일/일괄 검토 흐름 회귀: 과목 라벨 없는 입력이 기존과 동일하게
   동작하는지 확인(세그먼트 1개 fallback 경로).
